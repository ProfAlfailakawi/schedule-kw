# مراجعة طلبات الأستاذ وتوافقها مع الجدول

هذه المراجعة تخص فرع `fix/instructor-request-availability`. لا تعني نجاح
البناء وحده إثبات التوافق الكامل أو نجاح النشر.

## المسارات التي روجعت

- محرر الجدول والمقترحات: `Schedules.tsx` و`QuickCreatePopover.tsx` وواجهات
  `check-conflicts` و`suggest-slots` ومعالجات إنشاء/تعديل/حذف الموعد في `server.ts`.
- بطاقة الأستاذ: `/r/:token` وواجهات `/api/public/request/:token` والفحص الجماعي
  والمسودة والتوقيع والتحقق من التوقيع والرد وقبول بدائل القسم.
- وارد القسم وعمليات القرار والمعاينة والاعتماد: `InstructorInbox.tsx`،
  `requestHandoff.ts` و`slotTimeGroups.ts` و`instructorRequestThread.ts`.
- القواعد المشتركة: `scheduleIntelligence.ts` و`scheduleRegulations.ts`
  و`scheduleTime.ts` و`advancedIntelligence.ts` و`courseNature.ts`
  و`instructorRequestVerdict.ts` و`instructorIdentity.ts` و`studentDemand.ts`.
- القاعات: `locationRegistry.ts` و`locationRegistryEngine.ts` ومسارات السجل
  والمرافق المرافقة والاستعارة المعتمدة وفحص الحفظ النهائي.
- العرض: `requestVisual.ts` و`requestDayAutofillScript.ts` و`requestPageStyles.ts`
  والسكربت المضمن للبطاقة؛ بقيت مكونات العرض والتصميم الحالية.
- التخزين والتزامن: `repository.ts` و`referenceCache.ts` وحفظ الطلبات وكتابة
  المواعيد المفردة والجماعية والنسخ والاستبدال ونشر المقترحات والنسخ الاحتياطية.
- الاختبارات وسكربت المجموعة وبناء الإنتاج وCI ومسار نشر Cloud Run والتحقق
  من إصدار النطاق الرسمي. حالة التشغيل الفعلية تسجل في وصف PR والتقرير النهائي.

## ما بقي مختلفاً عمداً

الأستاذ يختار رغبة أو شعبة قائمة باسم «هيئة تدريسية»، ويوقع طلباً فقط.
اختيار القاعة والشعبة الجديدة والاستثناء والكتابة الرسمية تبقى للمنسق.
الحجز لا يظهر بتعبير «حجز مؤقت»، ولا يبدأ عند فتح الخيارات أو إنشاء المسودة.
الموافقة تسند صفوف الشعبة القائمة نفسها فوراً؛ الرفض يحررها. لا مؤقت قصير.

نمط 80+80+50 ليس ميزة جديدة ولا أولوية مطروحة للمستخدم. توجد حالة مقارنة
لمدد مختلفة بين الأيام حتى لا يتكرر خطأ دمج الأوقات، مع الحفاظ على قواعد
`main` الحالية، بما فيها 110+110 المعتمد لأربع ساعات.

## حدود الإثبات

اختبار ٤٠ طلباً شُغّل في التخزين التجريبي وعلى محاكي Firestore محلي، وليس
اختبار حمل على بيانات الجامعة أو عدداً من نسخ Cloud Run الحية. فحص Chromium
يغطي الاختيار واستعادة المسودة والملاحظة أثناء انقطاع الاتصال وعرض الهاتف؛
التوقيع والإرسال والمعاينة والاعتماد اختُبرت عبر HTTP ببيانات اختبار مستقلة.
لم تُستخدم قاعدة الإنتاج للاختبار، ولم ترسل رسائل لأعضاء هيئة التدريس.

المجموعة الشاملة تتضمن فحوصاً تحتاج نسخة البيانات التاريخية الخاصة؛ إذا لم
تتوفر يعلن المشغل ذلك وفق سلوك المستودع القائم. لم تُضف إخفاقات معروفة، ولم
تحذف أو تعطل اختبارات. لا يُدمج هذا الفرع إذا بقيت الفحوص المطلوبة فاشلة،
ولا يُنسب أي إصدار إلى الموقع قبل التحقق من النشر وبصمة الإصدار الفعلية.
