# إعداد مقترح دراسي للأستاذ — دليل التسليم

## ما الذي بُني ومن أين يُفتح

امتدادٌ لـ«الحوار مع الأستاذ» في **وارد الأساتذة**: يُعدّ القسم مقترحاً من عدة مواد لأستاذٍ واحد، يبقى **مسودةً منفصلة عن الجدول الفعلي** حتى يوافق الأستاذ ويُثبّته القسم.

- **من البطاقة:** زرّ «إعداد مقترح دراسي» داخل بطاقة طلب الأستاذ (وفي كل بند من الحوار).
- **من الشريط العلوي:** «المقترحات الدراسية» لبدء مقترح لأي أستاذ له طلب في الوارد، مع عدّاد ما ينتظر التثبيت أو رد الأستاذ.
- **صفحة الأستاذ:** رابط شخصي `/r/:token/proposal/:pid` يعرض الجدول الحالي والمقترح، ويوافق بالسجل المدني أو يطلب تعديلاً.

### العمليات الأربع
1. إسناد شعبة موجودة (هيئة تدريسية).
2. إنشاء شعبة جديدة لمادة موجودة (لا تُنشأ فعلياً إلا عند التثبيت).
3. تعديل موعد قائم.
4. استبدال موعد، مع إلغاء إسناد القديم أو حذفه.

### الواجهة — «استوديو المقترح» (إعادة بناء 2026-10-28، بند المالك N2)
**الجدول هو المساحة، والفرقُ يُرى عليه مباشرة.**
- **الرأس:** الأستاذ والحالة، وأربع بطاقات «قبل ← بعد» بشارة فرق ملوّنة (النصاب · الشعب · أيام الحضور · الموانع). القيمة القديمة مشطوبة حين تتغيّر.
- **شريط «ما تغيّر»:** مضاف · منقول · بديل · يخرج · ثابت — رمزٌ ورقم. الضغط على رقمٍ يُبرز مواعيده على الجدول. يُحسب بـ`proposalChangeSet` (في `src/utils/studyProposal.ts`) من الجدول الناتج والأشباح نفسها التي يعيدها المحرّك أو المعاينة الفورية.
- **على الجدول:** المضاف بحدٍّ أخضر ورمز «+»، والمنقول نحاسيّ وتحته «كان: …» (ما تغيّر وحده: الأيام أو الوقت)، والموضع القديم شبحٌ منقّط مشطوب يشير إلى الجديد، والتعارض مخطّط أحمر، والثابت هادئ. مفتاح «الأصل» يُظهر/يخفي الأشباح.
- **الشعب الشاغرة («هيئة تدريسية»):** المتوافقة منها تظهر على الجدول منقّطةً خضراء بزرّ «أسند» (ضغطة واحدة تضيف الإسناد إلى المسودة). الحكم من الخادم (`POST /api/study-proposals/vacancies` → `rankVacancies`): استبعاد ما يتداخل مع محاضرات الأستاذ، ثم الفحص الكامل نفسه (`evaluateProposal`) للمقترح كلّه مضافاً إليه «إسناد الشعبة كما هي». «متوافقة 100٪» = لا مانع ولا ملاحظة والفحص مكتمل ولم يزد عدد الموانع. تبويب «شاغرة» يعرض كل الشواغر بحكمها (متوافقة · للمراجعة · تتداخل · مانع · في المقترح) وأثرها على النصاب والأيام والفراغات قبل الضغط.
- **تبويب «التغييرات»:** كل مادة بنوعها وحالة فحصها، و«قبل ← بعد» بشريحتين (القديمة منقّطة مشطوبة، والجديدة بارزة وما تغيّر فيها مظلَّل).
- **الضغط على موعد** يفتح تفاصيله مع «قبل ← بعد» للمنقول، و«تعديل»/«استبدال» للقائم، و«أسند لهذا الأستاذ» للشاغرة.
- **السحب على فراغ** (سطح المكتب) يفتح بطاقة إضافة سريعة عند المؤشر كما كان.

**التخطيط المتجاوب** (يتبع عرضَ الجدول نفسه عبر container query، لا عرض الشاشة):
- ≥ 1000px: الجدول + لوحة جانبية بتبويبات (التغييرات · شاغرة · الفحص).
- < 1000px: تبويبات أعلى (الجدول · التغييرات · شاغرة · الفحص).
- الجدول الأسبوعي: عمود الوقت ورأس الأيام ثابتان (sticky) والأعمدة لا تضيق عن 112–128px (تمريرٌ أفقي داخلي عند الحاجة، لا تمرير للصفحة).
- عرض الجدول < 620px (الجوال أو نافذة ضيقة): يومٌ واحد بخطٍّ زمني — تبويبات أيام بعدد المحاضرات ونقاط التغيير/الشواغر، وبطاقات كاملة الاسم والشعبة والوقت والقاعة، والفراغ بين المحاضرات ظاهر، و«إضافة · اليوم» في الأسفل.
- أُلغي حجبُ المساحة عن الجوال (كان «متاح من الكمبيوتر» منذ #228).

### الفحص
نفس فاحص التعارضات المستخدم في الجدول (`scheduleConflicts` بمعامل افتراضي `hypothetical`)، وتُفصل النتائج إلى: **مانعة** / **ملاحظات للمراجعة** / **معلومات**. مع اقتراح أوقات بديلة (نفس النمط والمدة بخطوات ١٠ دقائق).

### الإرسال والرد والتثبيت
- حفظ مسودة، ومعاينة قبل الإرسال؛ رابط شخصي ونص رسالة قابل للنسخ (**النظام لا يرسل شيئاً ولا يدّعي ذلك**).
- نمطان للرد: مستقل (كل مادة على حدة) أو مترابط (الكل أو لا شيء).
- **نسخ المقترح:** كل تعديل جوهري يرفع النسخة، ولا تسري موافقة قديمة على نسخة أحدث.
- التوقيع بالسجل المدني؛ لا يُخزَّن، وتُحفظ بصمة ورمز تحقق فقط.
- التثبيت ذرّي ومتكرر الأمان (idempotent) مع إعادة فحص عند التنفيذ ومراجعة جفاف الصفوف (rev). دون `confirm` يكون تشغيلاً تجريبياً.
- صلاحية الرد منفصلة عن قفل/تجميد الجدول: القفل يمنع التثبيت لا الرد.

## الاختبارات
- `npm run test:study-proposal` — سلوكي + عقود المصدر.
- `npm run test:study-proposal-flow` — تدفق كامل على الخادم الفعلي (إسناد دون تكرار، إنشاء عند التثبيت فقط، تعديل/استبدال، تعارضات، موافقة جزئية، نمط مترابط، نسخ، جفاف، صلاحيات، الحوار القديم).
- `npm run test:study-proposal-page` — صفحة الأستاذ.
- `npm run test:study-proposal-studio` — «ما تغيّر» (`proposalChangeSet` على المعاينة الفورية وعلى شكل المحرّك) ومسار الشواغر حيّاً: حكمٌ لكل شاغرة، و«متوافقة» = إسنادها كما هي يمرّ بالفحص الكامل، وبعد الإسناد «في المقترح».
- كلها ضمن `npm test`. التحقق الأخير: `tsc --noEmit` و`npm test` و`npm run build` (راجع نتيجتها في وصف الـPR).

## لقطات الشاشة
- `studio-*` (القسم، بعد إعادة البناء) بأربعة عروض: 1440 و1024 و768 و375 — `01-open` (المساحة مع الشواغر المتوافقة)، `02-assigned` (إسناد شاغرة بضغطة)، `03-moved` (تعديل موعد: المنقول + شبح موضعه القديم)، `04-detail` (قبل ← بعد)، `05-changes` (تبويب التغييرات)، `06-vacancies` (تبويب الشواغر). مأخوذة من صندوق العرض التجريبي (`DATA_MODE=demo`) عبر Playwright/Chromium.
- `teacher-*` (الأستاذ): الانتظار، التفاصيل، الموافقة، طلب التعديل، المترابط، النسخة القديمة، المنتهي، المسحوب، المثبّت، الجدول قبل/بعد — سطح مكتب وجوال.

## حدود صريحة
- **لا سحب وإفلات** داخل الجدول؛ البديل الكامل هو النموذج ولوحة المفاتيح.
- فحص الشواغر الكامل محدود بأقرب 24 شعبة في كل مرة (الباقي «لم تُفحص»)، ويُعاد بعد كل تغييرٍ في المواد.
- **المقترح يقوم على طلبٍ موجود في الوارد**؛ أستاذٌ بلا طلب لا يظهر في الشريط العلوي بعد (يلزم مسار ينشئ طلباً/رابطاً له).
- **لا إرسال فعلي** (بريد/رسالة): يُنسخ الرابط والنص يدوياً.
- بيانات العرض في وضع `DATA_MODE=demo` ذاكرية؛ لم يُجرَّب Firestore الحقيقي هنا (المسار ذاته مُنفَّذ كمعاملة لكنه غير مُختبَر على قاعدة حيّة).
- أغلب الاختبارات تدقيق مصدري/سلوكي، والتحقق البصري يدوي عبر Playwright على Chromium فقط.
